# 业务逻辑文档生成提示词

下面这段可以直接复制给 Codex 或其他代码助手。把方括号里的内容替换成当前功能的信息；如果暂时不知道，就保留“待确认”。

```text
请为“[功能名称]”整理一份可长期维护的业务逻辑文档。

我的项目和范围：
- 后端项目：[绝对路径或仓库路径]
- 前端项目：[绝对路径或仓库路径]
- 数据库、Schema 或环境：[已知信息；不知道就写待确认]
- 功能页面、接口、表或关键词：[填写]
- 本次只读分析 / 需要同时修改代码：[填写]

请先阅读项目中的业务逻辑文档模板：
[模板绝对路径，或项目中的 docs/业务逻辑/业务逻辑说明模板.md]

工作要求：

1. 先做只读分析，按照“前端入口 -> 请求参数 -> Controller -> Service -> DAO/Mapper/SQL -> 数据库对象 -> 下游使用者”的链路追踪。没有明确要求时不要修改业务代码。

2. 查找并记录所有数据来源和触发入口，不能假设只有页面按钮会改变数据。至少核对：
   - 页面、按钮、路由和前端请求方法；
   - HTTP/API、Controller、Service、DAO、Mapper XML 和存储过程；
   - 应用定时任务、Quartz、批处理和启动初始化逻辑；
   - Oracle 的 DBMS_SCHEDULER、DBMS_JOB、触发器、视图、物化视图、同义词和 DB Link；
   - MQ、WebSocket、回调、外部系统、文件导入和手工 SQL/补数脚本。

3. 对关键字段列出全部写入路径：哪个接口、任务、触发器或脚本会写入，什么条件下写入，值从哪里来，是否会覆盖历史值，是否有校验。不要只记录本次需求涉及的一个接口。

4. 记录角色、权限和数据范围：谁可以查询、修改、审核、导出或结算；单位、租户、区域、船舶或其他隔离条件在哪里生效。

5. 还原实际状态流转、分支、驳回、重试、重复提交、事务失败、并发和幂等行为。以当前代码和数据库证据为准，不要根据字段名、旧注释或个人经验猜测业务含义。

6. 分清以下内容：
   - 当前代码已经证实的行为；
   - 只在某个环境存在、需要 Oracle/浏览器/部署验证的行为；
   - 需要业务负责人确认的规则。
   未确认的内容统一标记为“待确认”，并写明需要谁提供什么信息。

7. 文档中使用文件绝对路径或仓库相对路径、类名、方法名、接口地址、表名和字段名作为定位依据。不要只写模糊的“后端处理”“系统自动更新”。

8. 如果发现代码注释、页面显示、实体字段说明和实际 Service/SQL 行为不一致，请分别记录“现行实际行为”和“文档/注释差异”，不要自行替换业务规则。

请按模板输出以下内容：
- 功能定位和范围；
- 项目、页面、按钮、接口和后端文件映射；
- 角色、权限和数据范围；
- 所有数据来源和触发入口；
- 主表、关联表、视图、存储过程和关键字段语义；
- 端到端流程、状态流转、驳回和异常分支；
- 接口调用链、事务边界和全部写入路径；
- 可验证的业务规则和不变量；
- 报表、结算、通知、缓存和外部系统等下游影响；
- 配置、部署和环境依赖；
- 已执行的验证、未覆盖的验证；
- 已知边界、待确认项和变更记录；
- 以后修改该功能时的检查顺序；
- 需要我或业务人员补充的信息清单。

输出要求：
- 先给我一段简短结论，说明你确认了什么、还缺什么；
- 再输出完整 Markdown 文档；
- 所有关键结论都附文件、类、方法、接口、表或字段依据；
- 不要编造数据库 Job、触发器、字段含义、状态责任人或业务规则；
- 如果数据库、生产环境或外部系统无法访问，要明确写“本地未验证”，并告诉我需要提供什么查询结果或日志。
```

## 使用时最好一并提供

为了减少来回询问，发送提示词时尽量补充：

- 功能名称、业务人员叫法和旧系统叫法。
- 前后端项目路径、已知页面路径和接口路径。
- 已知表、视图、存储过程、触发器或定时任务名称。
- 测试数据、异常时间、日志关键字和用户反馈。
- 哪些历史行为必须保持，哪些规则本次明确要改变。
- 是否只生成文档，还是允许同时修改代码和文档。

如果只想生成文档，明确写“只读分析，只创建或更新业务逻辑文档，不修改源代码”。如果还希望补齐代码注释或创建 Skill，需要单独写明。

## 封装成 Skill 的方式

这套流程适合封装成一个自动发现的 Skill，例如 `business-logic-documenter`：

```text
business-logic-documenter/
├── SKILL.md
├── agents/openai.yaml
└── references/
    └── 业务逻辑说明模板.md
```

`SKILL.md` 只保留触发条件、分析边界和工作流程；详细模板放在 `references/业务逻辑说明模板.md`。使用时可以写：

```text
$business-logic-documenter

请整理 [功能名称] 的业务逻辑文档。项目路径是 [路径]，只读分析，不修改源代码。
```

Skill 可以放在个人 Skills 目录中供多个项目使用，也可以放在项目内作为团队共享版本。安装到个人 Skills 目录前，需要确定 Skill 名称和安装位置；本项目当前先保存了提示词和文档模板，没有安装全局 Skill。
